# 从问题出发的两篇精读样章

这批样章回应用户 2026-10-19 的最新授权：自行选择一篇 Hugging Face 论文及一个有工程学习价值的项目，用连续正文，展示一个最小问题怎样因新约束逐步长出设计。它更新了 D-027 的“等用户提出兴趣后再选题”阶段，不代表把全榜都改成推荐。

## 选题依据

**推理**：PagedAttention 的资源增长、共享与调度可沿同一请求逐步展开，完整论文和消融可获取；ContextMode 在当日周/月榜，执行到索引、检索的主链路可固定版本并实际运行。因此可以先用一篇经典系统论文和一条工程实现验证写法。

**理由**：两者都能回答“新组件解决了上一步的什么缺口”，又处理不同层次的资源；容易识别把显存布局与 prompt 信息选择混为一谈的错误。选择不是依据机构或热度分数。

**对比**：当日最新模型论文需要更高的训练/推理复现成本，容易只能转述结果；大平台项目的全景容易变成模块目录。先做机制范围明确的两篇样章，正文约 5,522 / 6,019 字符，后续再由用户评价是否真的帮助理解。

**风险**：经典论文不代表当前引擎；项目案例的已知检索词不代表开放任务能力。按约束展开是教学重建，不是伪造开发历史。两个草稿均标为 needs_review，不自动公开或标记读懂。

## 可检查的材料

- `paper.mjs`、`project.mjs`：原创正文、固定来源、论断与覆盖记录。
- `figures.mjs`：独立沙箱内的交互教学模拟 / 实测回放，明确不在浏览器运行模型或上游项目。
- `verification.json`：本机合成日志的协议回执摘要、检查条件、上游部分测试结果。不是公开生产基准。
- 本机完整资料：`D:/Agent-Proj/jarvis-reading-samples/`，保留原 PDF、HTML、HF 元数据、固定 commit 源码、测试日志、回执与输出。下载来源 SHA-256 见 `manifest.json`；原文不进入公开仓库。

## 本机导入

先确保本机阅读台运行；使用已经配置的作者凭证，勿在聊天粘贴密钥：

```powershell
node --env-file=apps/web/.env.local authoring/samples/2026-10-19/import.mjs
```

导入只追加两个精读草稿，原有版本和私人书架状态不改。正文生成使用当前 Codex 会话；网页的辅助问答继续使用已有模型配置。`import.mjs` 从本机归档读取 HF 原始元数据，因此换机需先恢复上述归档。作者 API 的自选论文元数据支持使入库无需伪造当日榜单。
